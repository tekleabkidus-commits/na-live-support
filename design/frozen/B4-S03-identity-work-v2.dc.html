Identity work

Checklist rows C01–C07 · Doc 08 FR-04, FR-05, FR-07, FR-09, FR-10, BR-02, EC-03, EC-05 · US-03 · AC-01. Adding an identity, refusing one that belongs elsewhere, and pulling one off a profile. The confirm-phrase input is taken verbatim from B1-S04.

Every screen here exists because of one refusal in Doc 08: the system never links identities by itself. A phone number typed into a chat stays text. The resolver matches or creates, and consolidation is a person's decision with their name on it — because a wrong silent link in a betting product misroutes somebody's money.

The shared phone, which the design does not try to solve

One phone, three brothers, three players — common here, and Doc 08 is explicit that it is not a bug to be fixed with a merge. The number sits on one profile, the others are blocked from adding it, and the agent handles the reality with a note and the duplicate-player-ID hint.

Forcing a merge would fuse three people's ticket histories permanently to make one form field behave. The refusal is the feature.
