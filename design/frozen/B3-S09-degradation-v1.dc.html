K05, K06 · Failing without taking the site with it

Doc 13 FS-05, NFR-05, NFR-06, BR-01

K05 · Help down, Messages up

Drawn in B3-S04 and not redrawn here: the Help tab shows one line saying articles are unavailable and points at chat, while Messages carries on. They are separate failure domains, and the widget is built so one taking the other down is not possible rather than merely unlikely.

K06 · Below the support matrix, or blocked outright
The dashed circle is not drawn in the product — it marks where the launcher would have been.

An old browser below the matrix, a host CSP that blocks the frame, a CDN that will not answer — in all three the widget does not mount, says nothing, and leaves no trace on the page. No error card, no console shouting, no half-rendered bubble. The host page is exactly as it would have been if the snippet had never been pasted.

The operator learns about it instead: the loader beacons the reason, and Health names it with the fix — the CSP header to paste, the browser that fell below the line. That asymmetry is the whole posture. A dead widget is invisible to the player and loud to the person who can repair it.

The rule underneath every frame on this page: the widget can never be the reason an operator's site broke. It outranks every feature, including the ones on this screen.
