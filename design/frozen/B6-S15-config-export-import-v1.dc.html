Config export & import

Bulk convenience without bulk opacity. An import is not one action that either worked or did not — it is a list of individual changes, each previewed, each ticked or not, each audited. The diff table is therefore the screen; the upload is a formality before it and the apply is a consequence after it.

The hardest thing to design here is the failure. When an apply stops halfway, the instinct is to roll back — and that instinct is wrong: these are 200 unrelated settings, not one transaction. Undoing 84 good changes because the 85th failed leaves the tenant in a state nobody chose. So the results screen shows applied, failed and not-attempted as three separate lists, says plainly why nothing was reversed, and becomes the worklist for finishing the job.

Components are B1-DS verbatim; the shell and the per-key anatomy are B6-S11's.

Delivery note

Delivered: O01 (export with its content summary and the three exclusions stated as prominently as the inclusions — §A light), O02 (diff table grouped by area, per-row checkboxes with tri-state group headers, a validation badge on every row — §A dark), O03 (progress, then the three-list results with audit links — §B both themes, §C both themes), O04 (partial apply, valid subset only, nothing merged silently — §B both themes), O05 (version incompatibility with the delta named and no partial-schema attempt — §B both themes), O06 (mid-apply failure with applied / failed / not-attempted separated and the no-rollback reasoning — §B both themes, §C both themes), O07 (cross-tenant stated, not mysteriously failed — §A light, §B both themes).

Deviations to record: none. 375 is read-only per the ruling, with the results worklist fully legible.

One thing I want your eye on: the no-rollback explanation is copy doing engineering's job. It is the right behaviour and the screen defends it well, but an operator who disagrees has no recourse in this design — there is no “undo this run”. If you want one, it is a real feature with its own reverse-diff and its own confirm, not a button; worth deciding now rather than after someone asks for it mid-incident.
