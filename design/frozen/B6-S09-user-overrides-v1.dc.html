B6-S09-user-overrides-v1 rows H01–H12

User overrides & effective permissions

Section H, and the whole screen exists to answer one question an admin asks under pressure: “why can this person do that?” Doc 03 §8 answers it with a precedence order — user deny beats user allow beats role beats implicit deny — and the design's only real job is to say that in words nobody has to be taught. So the verdict is never a bare chip: it is a chip plus the sentence that produced it, and the four levels are shown in the document's order, every time, including the ones that did not decide.

RBAC only. The user list, invitations and account lifecycle are Doc 02 and deferred to Batch 7 by your ruling — this screen is reached from a person's profile and only ever edits their exceptions. Components are B1-DS verbatim; the shell is B6-S07's.

One thing I want your eye on: the precedence explanation always shows all four levels, including the ones that did nothing. It costs four lines on every verdict. The alternative — showing only the deciding level — is tidier and, I think, worse: an admin who only ever sees the winning line never learns the order, and the order is the thing that surprises people.
