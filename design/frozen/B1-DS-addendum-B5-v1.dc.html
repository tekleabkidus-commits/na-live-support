B1-DS addendum — from Batch 5

Four component sets that Batch 5 created and that later batches will need. They are promoted here so they are reused from the system, never rebuilt by eye — the same route the B12-S01 lightbox chrome took, and the discipline whose absence caused the drift corrected in B12-R01.

Mobile confirmation

B5-S02 v2 §F · owner ruling v3

This component carries the safety load the fat-finger policy used to. Batch 5's v3 ruling made every feature phone-executable, and this is what replaced the restriction — so it is not decoration, and any future batch enabling a destructive action at 375 must use it.

Light
Four rules, in order of importance
1Restate the consequence in nouns — who, how many, until when. Never repeat the button label back at the user.
2The primary button carries the specific verb, in the tenant's language — the action, never OK and never Confirm. Batch 5 ships these in Amharic; the English below each is a gloss for this document, not the shipped label.
3Three weights, visually distinct — reversible, affects-others, irreversible.
448px buttons, confirm on the right — away from the thumb's resting arc on the cancel side.

§C

Reduced motion — four equivalences

B5-S11 v2 §D

Each equivalence keeps the information and removes only the movement. Any new animated element in a future batch states its own equivalence at review — that is the inheritance obligation this section creates.

ElementNormallyReduced motion
Live markerDot pulsesStatic ring, same meaning
SparklineDraws left to rightAppears complete
SkeletonShimmer sweepsFlat, no sweep
Page changeTV rotation cross-fades; slide-overs slide inBoth cut instantly. Position and focus land identically.
The one exception: a wizard's per-chunk progress bar keeps advancing under reduced motion. It is the only signal that a multi-minute irreversible operation is still running, and a frozen bar reads as a hang.
§D

Announcements

B5-S11 v2 §C · Doc 15 §13

Doc 15 §13 asks for polite and batched and stops there. Every threshold below is a Batch 5 decision, promoted so later batches inherit the cadence rather than each picking their own.

What changesAnnouncedPoliteness and timing
Alerts arrive“3 new alerts. Most urgent: SLA breached, Deposits.”politeBatched over 5 s. Count plus the highest severity, never each in turn.
A breach lands“SLA breached. Ticket 4812, Deposits, first response missed by 4 minutes.”assertiveBreaks the batch. The only class allowed to interrupt.
A countdown runs“Yonas Tesfaye, temporary in Deposits, 10 minutes left.”politeAt 60 min, 10 min, 1 min and expiry. The visible number still ticks every second.
A number refreshes— nothing —offA board reading its own numbers aloud every ten seconds is unusable.
Connection degrades“Live updates lost. Refreshing every 30 seconds instead.”politeOnce per state change, not repeated while it persists.
A wizard advances“Step 2 of 4. Decide what happens to each reference.”politeOn step change; per completed chunk during execution, never per ticket.

How this file is meant to be used

On your approval this becomes part of B1-DS. From then on, Batch 6 onward takes these four sets from here verbatim — a chart, a mobile confirmation, a reduced-motion equivalence or an announcement cadence is never re-derived from a screenshot or from memory.

Nothing here is new. Every value is lifted from the frozen Batch 5 files named in each section header. If a value here disagrees with its source, the source wins and this file has a bug — report it rather than following it.

Two hard-won constraints worth reading before you draw a chart: #7E7A6E is unusable for cell fills and labels at 9–10px against any ink, and #A29D91 works only with #22211D. Those two facts cost two review cycles in Batch 5 and are the main reason this addendum exists.
