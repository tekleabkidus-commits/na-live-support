Checklist rows: C01 · C02 · C03 · C04  |  Doc 10: §8 History · FR-08 · FR-09 · FR-14 · FR-16 · §9 Diff view · §13 · T-06 · EC-05 · EC-06 · EC-07 · SEC-04 · AC-06 · AC-07 · SS-04 · X8

Baseline: the built resources/js/Pages/Admin/Kb/History.vue (immutable snapshots newest first, block-aware diff older → this, restore-as-new-draft) and resources/js/Pages/Kb/Tombstone.vue (the labeled-degrade landing: Current / Retired-with-link / Retired / Unknown, never a 404), refined. Differs from build: (1) the history is a two-pane page inside the Backoffice chrome — version list beside the diff — where the build stacks a diff summary under each version row; (2) the diff renders the §9 block anatomy (green-tint added with “+”, red-tint collapsed removed stubs with “−”, paired before/after for changed with the differing words marked) and the §13 prev/next changed-block landmarks, where the build prints kind + key per entry; (3) the restore confirmation is drawn (§8 History: “explaining it creates a new draft”) — the build restores on click; (4) the tombstone is drawn in its two real homes — the widget Help panel (B3-S04’s reader idiom, brand-neutral placeholder tokens; Doc 16’s theme paints it) and the staff citation landing with the version-pinned snapshot — where the build is one bare state line.

Designed absences: no edit affordance on any version (snapshots are immutable, AC-07); no Delete anywhere — archive keeps the record and its tombstones (X8; erasure is Doc 17’s workflow); no 404 and no failure vocabulary on the customer-facing tombstones (“updated”, “no longer available” — never “error”, “missing”, “broken”); the removed stub is collapsed, never hidden; nothing by colour alone — every diff block carries its glyph and its word.
