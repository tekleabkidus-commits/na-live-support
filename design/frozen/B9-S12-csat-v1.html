Baseline: the built resources/js/Pages/Workflow/Csat.vue (the three registered csat.* keys as settings rows, the per-language labels as the shipped strings with Doc 16 named for overrides, the event note), refined. Differs from build: (1) each row carries the full six-part contract — label, key, description, typed control, provenance, reset — and the CONSEQUENCE BEFORE SAVE with a live count (the build has label + input); (2) the customer-facing renders are drawn from the FR-25 contract in their real homes — the Telegram device frame in both modes and the widget thread with the B3-S03 star row — the build has none (checklist silence 2: the widget row is Doc 13’s surface, drawn here from the contract only); (3) the rail states the trigger, suppression, single-response and low-score rules and the three events with their payloads.

Designed absences: no incentive, nudge, reminder cadence or reward copy, and no setting that could add one (BR-07, X6); no second prompt inside the cooldown; no prompt to an RG-flagged customer (N-11’s neighbour — the suppression contract); no failure vocabulary on the customer surfaces (“window closed”, never “error” or “expired survey”); no colour-only state — the closed star row is dashed AND worded; the widget stars are a radiogroup with labels (AA).

What a survey is
Triggerticket resolved by a person, or resolved by the AI (Doc 06 FR-06, Doc 09 FR-09) — one survey per resolution eventSuppressedsame customer within the cooldown · customer is RG-flagged (Doc 08 FR-15 suppression contract) — no prompt, and csat.sent is not emittedCaptureone tap 1–5; optional comment; exactly one response per survey — an edit within 1 h replaces itLow score≤ 2 raises a review item for the supervisor feed and Doc 09’s loop
Events · Doc 15’s source of truth
csat.sent{ticket, resolver_type: human | ai, channel}emitted when the prompt leaves; suppressed surveys emit nothing
csat.received{score 1–5, comment?, ticket, resolver_type}once per survey; an edit within the hour re-emits with the replaced score
csat.expired{ticket, resolver_type}at the window’s end, before any late tap can arrive
Every survey emits csat.sent / csat.received / csat.expired for reporting (Doc 15). Spam and test traffic never count (N-14).
Designed absences
No incentive, no nudge. There is no reward text, no “rate us 5 stars” copy, no reminder cadence and no setting that would add one — CSAT is measurement, not marketing (BR-07). The prompt is one message; silence is a valid answer.
