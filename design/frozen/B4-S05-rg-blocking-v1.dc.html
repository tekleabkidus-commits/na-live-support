The RG flag, and blocking

Checklist rows E01–E07 and F01–F05 · Doc 08 FR-14, FR-15, FR-18, BR-03, EC-06, EC-07, SEC-01, §8, §9 · Doc 04 FR-03. Two sensitive states in one screen set because they share a discipline: both are about what the interface refuses to say.

The responsible-gaming flag is the hardest requirement in Batch 4. Not because the banner is difficult — because an agent without the permission must not be able to work out that a flag exists. No lock, no greyed row, no gap where something was removed, no “restricted” label. The unpermitted profile is not a redacted version of the permitted one; it is a different, complete page.

Put these two side by side and the second has no seam. No banner slot, no empty space where one was, no dot on the tab, and the page begins where it always begins. The API never sends the field, so there is nothing for a curious agent to find in the markup either.

Why absence and not a lock

A locked row tells you a secret exists and who it is about. On a support floor that is enough: the agent knows this customer has something, and the guessing does the damage the permission was meant to prevent.

So the rule is stricter than hiding a value. Two agents comparing screens over a desk should not be able to tell which of them can see more — and that only holds if the unpermitted view is a complete page in its own right, which is what these two frames are drawn to prove.

F01–F05 · Blocking, and its honest limit

Doc 08 FR-18, EC-07, §8 · Doc 04 FR-03
F01 · Light — every channel at once
Block ዮሴፍ ካሳ
This is wider than blocking one conversation
  • All 4 conversations go quiet, on every channel
  • New messages from them are quarantined, not delivered
  • Nothing can be sent to them until this is lifted
If you only want one channel quiet, block the conversation instead — that leaves the rest of their contact working.

A new Telegram account is a new customer — the block did not follow them, and nothing links the two automatically. The duplicate hint is usually how an agent notices. From here they can merge the two profiles and inherit the block, or block this shell on its own.
Doc 08 calls this a documented limitation rather than a bug. Auto-linking the two would mean guessing that a phone or an ID makes two accounts the same person — the exact guess this product refuses to make anywhere else.
