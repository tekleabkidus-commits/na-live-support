B6-S03-reply-window-settings-v1 rows D01–D04

Reply-window administration

Four rows, one small surface, and one genuinely unusual rule to make legible: this setting can be tightened but never loosened, and the platform will tighten it behind the operator's back when Telegram proves the window was shorter than configured. A number field that silently disagrees with its own stored value would be a bug; here it is the specification, so the calibration has to be visible next to the control rather than buried in a changelog.

Every part is B1-DS verbatim — including the reply-window chips, which are shown here as previews so an admin setting the threshold can see the exact chip an agent will get. The per-key anatomy (label, description, typed control, validation, provenance, reset) is Doc 16's contract, applied here as rows J03–J06 will apply it everywhere else.

The composer's closing / expired / paused cards are Doc 05's contract for Doc 07 and are Batch 1 law. They are not rebuilt here.
