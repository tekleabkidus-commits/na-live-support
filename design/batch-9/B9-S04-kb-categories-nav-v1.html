B9-S04 — KB categories + the palette / nav entry — v1

Checklist rows: D01 · D02 · D03 · D04  |  Doc 10: FR-01 · FR-10 · FR-15 · FR-18 · FR-19 · §8 Manager layout · §13 · EC-02 · EC-03 · SEC-01 · BR-03  |  Precedents: P8 (the shell’s one KB nav entry, S10 countersigned) · P-NAV (S12)

Baseline: the built category pane in resources/js/Pages/Admin/Kb/Manager.vue (a flat list of buttons) and the built doors behind it — create · update · impact · reassign · delete under kb.categories.manage, CategoryTree with MAX_DEPTH = 3 — refined. Differs from build: (1) the tree is drawn as a real tree (depth, grips, ↑↓←→ buttons, counts, the INTERNAL tag) where the build lists top-level buttons only; (2) a category EDITOR is drawn — every FR-01 field (name per language, slug, description, position, icon, parent, ai_usable, visibility default) — where the build has no editor page, only the doors; (3) the EC-03 delete-with-reassign dialog and the EC-02 AI-usable-off consequence dialog are drawn from the built impact door’s fact (“N would leave the chatbot”); (4) the palette row is drawn exactly as built (open-kb → “Open the Knowledge Base”, beside the P-NAV Workflow row) — no new shell entry is invented.

Designed absences: no “Add subcategory” and no → (indent) on any node that would make depth 4 — absent, not greyed (FR-01); no “Delete category” while it holds articles — reassign is the only path (EC-03); no per-article AI-usable switch (inheritance is the rule, FR-10); no hard delete (A-43 soft delete); a category’s visibility default never rewrites an existing article’s audience (BR-03); the shell gets ONE KB entry (P8) — no second nav item, no sub-navigation.
