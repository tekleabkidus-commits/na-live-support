**ADR 0021 draft — `docs/adr/0021-vault-secrets-interim.md`:** Status: accepted (interim). Context: C-13 says secrets live in the vault and the DB stores references; Doc 18 (infrastructure) owns the real vault and is not built; Doc 13 FR-07 needs a per-widget HMAC secret with rotation and an overlap window NOW. Decision: one platform-shaped table `vault_secrets(ref PK, tenant_id, ciphertext, created_at, retired_at)` behind the `vault://<namespace>/…` ref contract; ciphertext = the application encrypter under `APP_KEY`; grants INSERT(ref, tenant_id, ciphertext) + UPDATE(retired_at) only, no DELETE, RLS forced; the reader (`VaultInterim`) reveals in memory for one comparison and never returns, logs or serializes the plaintext; the scrubber redacts both value shapes (P-RIDER1-FIX); audit rows carry neither value nor ref. Consequences: a compromise of `APP_KEY` + a dump reveals the secrets (the interim's honest limit — Doc 18's vault removes it); rotation history is the row set ordered by DB time; **Doc 18 replaces the table with the real vault behind the same `ref` contract and retires this ADR** ([D18] reopener, by name). Alternatives rejected: plaintext column (C-13 violation); env-only secrets (no per-widget rotation); building Doc 18's vault early (build order).
