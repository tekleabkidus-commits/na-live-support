# ADR 0020 — Widget bundle stack: Preact + signals, a hand-rolled Pusher-protocol client, Vite library build, Playwright 375/widget projects

**Status:** APPROVED with the SESSION-13 plan (advisor ruling STOP-L, owner's dependency approval rides it; plan of record 0f2949e). Filed at step 6 BEFORE the first `npm install` under `widget/`.

## Context
Doc 13 T-01 fixes the architecture: "loader (vanilla, no deps) + panel app (Preact + a minimal store); build produces immutable hashed bundles + the per-widget-key loader shim". NFR-01 fixes the budgets: loader ≤ 5 KB gz, core ≤ 50 KB gz (Help/forms lazy-chunked). FR-21/T-04 fix the transport: Reverb (the Pusher protocol) primary, polling fallback on the same cursor endpoint. CLAUDE.md §3 fixes the stack: "Standalone Preact iframe bundle — separate build, separate CDN channel, no Laravel assets". `/widget` was empty; no Reverb JS client exists anywhere in the repo (the staff app scripts its realtime through a test hook — Doc 07 T-07's seam).

## Decision
1. **`preact` + `@preact/signals`** — the stack's own choice; signals are the "minimal store" (≈ 4 KB + 2 KB gz).
2. **A hand-rolled Pusher-protocol WebSocket client** (`widget/src/transport/reverb.ts`) instead of `pusher-js` (~30 KB gz against a 50 KB core budget) or `laravel-echo` (needs pusher-js). Scope: connect (`/app/{key}?protocol=7`), `pusher:connection_established`, `pusher:ping/pong`, private-channel subscribe with the auth signature from the widget's own broadcasting-auth door (Doc 02's visitor principal), `subscription_succeeded`/`subscription_error`, event dispatch, exponential reconnect + resubscribe, and the drop/up signals the polling machine consumes. Proven against the REAL Reverb in the HARNESS before the panel renders a message (STOP-L's condition): connect, channel-auth with the visitor principal, resubscribe on reconnect, cursor convergence after a socket kill. Gzipped size stated here at the first build: [FILLED AT STEP 6].
3. **Vite library build** (`widget/vite.config.ts`, separate from the app's Vite): entries `loader` (vanilla TS, no imports) and `panel`; output content-hashed immutables under `public/w/` (`core.{hash}.js`, `help.{hash}.js`, `forms.{hash}.js`, `loader.{hash}.js`); the per-key shim `GET /w/{widget_key}.js` is a Laravel route (60 s cache) resolving `ref_widget_bundles` (FR-04 pointer semantics). No Laravel assets, no Inertia, no Tailwind in the bundle; tokens from `resources/css/design-tokens.css` are COPIED into the widget's own CSS by the build (the hex-extraction script proves them — the same frozen sources).
4. **Playwright projects** `widget` (chromium, desktop) and `widget-375` (chromium, `devices['iPhone 13']` viewport) pointed at the HARNESS customer origin; `workers: 1` kept (the shared backing store). Firefox/WebKit are not installed on the dev box; CI's Stage 4 installs chromium only — the NFR-05 matrix rows beyond chromium are stated [D19]/[OA], never claimed.
5. **Gates from the first build:** `widget-bundle-budget` (loader ≤ 5 KB gz, core ≤ 50 KB gz, lazy chunks named — read from Vite's manifest; R-05) and `widget-vocabulary` (the failure-vocabulary denylist over every `widget.*` string, en + am, positive control; R-D13-5.1) — both in `registries/gates.yaml`, both falsified + restored at landing.
6. **`make lint`** gains `widget/` (eslint + `tsc --noEmit -p widget`).

## Consequences
Exact versions pinned in `widget/package.json` (no `^`/`~`): preact, @preact/signals, vite, typescript, esbuild via vite. The hand-rolled client is Doc 13's to maintain; its contract is the Pusher protocol v7 subset above — anything beyond (presence channels, client events) is out of scope on purpose (a visitor's channel is private; client events never reach the application). Bundle growth is a gate, not a review item (R-05).
